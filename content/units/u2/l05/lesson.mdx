# Small fix I: clippy cleanups under workspace lints

Your first real goose PR will probably be a clippy cleanup, and clippy PRs
fail on culture more than on code. The workspace declares its policy in the
root `Cargo.toml` at `[workspace.lints.clippy]` (`Cargo.toml:18`). Two lines
there teach the whole story:

- `string_slice = "warn"` (`Cargo.toml:20`) — slicing `&s[0..1]` is genuinely
  dangerous: str slicing always panics at a non-character boundary, and once
  non-ASCII text is in play, a byte index one off — `[0..3]` instead of `[0..4]`
  on `José` — flips a working label into a runtime panic. The lint pushes you
  toward `get(..)` + handling `None`. That's a *correctness* lint the team wants
  enforced.
- `uninlined_format_args = "allow"` (`Cargo.toml:19`) — the team *decided*
  not to chase stylistic churn. Lint policy is a conversation, not a default.

## The gate: warnings are errors

`Justfile:13` runs `cargo clippy --all-targets -- -D warnings`: every warn-level
lint becomes a hard error at the PR gate. And `AGENTS.md:117` makes the human
side explicit: *Never merge without running clippy*. So a cleanup PR's job is
to get the tree from "clippy complains" to "clippy passes with `-D warnings`".

## Cleanup workflow that reviewers respect

1. **Reproduce first**: run `cargo clippy --all-targets` and capture the exact
   lint names (e.g. `clippy::string_slice`) — never fix what you can't see.
2. **Understand the lint's rationale** before changing code. `string_slice`
   means "this can panic on non-ASCII input when the byte index splits a
   multibyte char" — the fix usually swaps in `get(..)` or byte-safe indexing
   with an explicit `Option`/`unwrap_or` decision, which you must make *on
   purpose*.
3. **Fix at the source, not with attributes.** Adding `#[allow(...)]` is a
   last resort that needs a justifying comment — a PR full of allows gets
   rejected because it hides, not fixes.
4. **Never `clippy --fix` blindly on a shared codebase** — it rewrites
   semantics-adjacent code (auto-`get(..)` can silently change error paths)
   and creates unreviewable diffs. Hand-fix, review each hunk.
5. **Keep the PR single-purpose**: lint cleanups only — no refactors hiding
   inside them. `git add -p` is your friend.

<FounderLens>

Why workspace-level lints instead of per-crate? A single policy at the root
`Cargo.toml` means every contributor, IDE, and CI job judges code identically,
and a policy debate happens once. Tradeoff: one globally-denied lint blocks
legitimate local uses — the escape hatch is a scoped `#[allow]` *with a
comment*, reviewed like code. Where it breaks: contributors who fix warnings
without reading the rationale produce "neutral-looking" diffs that quietly
change behavior (a `.get()` swap that turns a panic into a silent default).

</FounderLens>
