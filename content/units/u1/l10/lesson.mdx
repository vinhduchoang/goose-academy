# Session & context: manager, compaction, context_limit, history search

The plan names manager, compaction, `context_limit`, `chat_history_search` — all real, with one upgrade: compaction now lives in its own crate `goose-context-management`, and `Session` moved out of `session/mod.rs` into `session/session_manager.rs`.

## The SessionManager and its Session

`crates/goose/src/session/session_manager.rs:316` — `SessionManager` owns the data directory, the session registry, and persistence. `Session` itself (`session_manager.rs:62`) is the persisted record: `id`, `working_dir`, the whole `conversation: Option<Conversation>`, `usage` + `accumulated_usage` + `accumulated_cost` (the token/cost ledger), `goose_mode` (session-pinned posture), `recipe` state, and `last_message_snippet` (cheap list views without loading the conversation). Everything the app shows in the session list is *outside* `conversation` — that's the storage-shape lesson: metadata hot, messages cold.

## context_limit

Depth of the attention window comes from two layers: `crates/goose/src/context_limit.rs:12` (`get_local_context_limit`) does the canonical local lookup, while `goose-provider-types/src/context_limit.rs:9` (`ContextLimitResolver`) is the infallible layered resolver the `Provider::get_context_limit` trait default calls (l06): explicit override → configured limits → canonical metadata → global default. If you want to see the whole limit decision for one model in one place, the resolver is the file.

## Compaction

Compaction is what happens when the conversation approaches the limit. In v1.49.0 the brain was extracted to `crates/goose-context-management` ("summarizing a message history down to a single message so a conversation can continue past a model's context window" — the crate doc, `lib.rs:1`). Layers: `summarize.rs:124` (`summarize`) produces a summary `Message`; `model.rs` defines the trait seams (`CompactionModel`, `TokenEstimator`); `templates.rs` ships the prompt templates.

Goose wires it in `crates/goose/src/context_mgmt/mod.rs`:

- `check_if_compaction_needed` (`context_mgmt/mod.rs:225`) decides *whether* — token count vs the limit vs `GOOSE_AUTO_COMPACT_THRESHOLD` (read in the machine constructor at `agent.rs:1650`).
- `compact_messages` (`context_mgmt/mod.rs:70`) performs it — calls `goose_context_management::summarize` (`:354`), splices the summary into the conversation, and re-estimates usage.
- The state machine wraps this as `CompactionOperation` (`state_machine/ops_compaction.rs:47`), with its own hard cap: `MAX_CONTEXT_ERROR_COMPACTIONS = 2` (`ops_compaction.rs:24`) — after two *context-length-error-triggered* compactions in one run, goose stops and surfaces the error instead of looping.

## History search

`crates/goose/src/session/chat_history_search.rs:50` — `ChatHistorySearch` powers "what did I say about X" across *sessions*: it iterates indexed conversations, matches keywords/substrings (`ChatRecallResult` / `ChatRecallMessage` types carry the found snippets + metadata), so the search UI answers with citations instead of hitting a database. It exists because `conversation` blobs are not queryable JSON — search must be a purpose-built pass.

<FounderLens>

**Problem solved:** unbounded conversations + bounded model context. The session/compaction split keeps hot UI data outside the message log, prices the "how close to the wall are we" question via one resolver, and pays down the debt with layered compaction (threshold → summarize → tool-pair summaries) instead of dropping messages.

**Tradeoff:** compaction is *lossy by design* — a summary replaces real turns, so "verify history survives" is a test of the splice, not a promise of byte fidelity. Extracting `goose-context-management` made the logic cross-language-testable (the crate is exposed through goose-sdk bindings) at the price of an extra crate boundary and trait indirection.

**Where it's heading:** compaction is fracturing into tiers — full `compact_messages`, targeted `tool_pair` summarization, and per-turn `moim` (memory-of-intent-messages) — each with its own threshold and trigger; watch `context_mgmt/mod.rs` grow more `*Operation`s.

**Where it breaks:** after compaction the conversation *no longer contains* what the model said — history search, steering, and recipe validation all read pre-compaction history; a bad summary silently erases facts the user can still see in the UI. The double-compaction cap (`MAX_CONTEXT_ERROR_COMPACTIONS`) is the tripwire against compaction loops.

**Where you'd extend it:** a compaction guardrail — refuse to compact unless the summary preserves the N most recent tool-result ids; or a per-compaction checkpoint copy for rollback. Both plug into `CompactionOperation` without touching the extract crate.

</FounderLens>
