# Data types: scalars, mut, shadowing, inference

JS gives you one numeric type. Rust gives you a menu — and chooses very deliberately.
Goose is full of `usize` for token counts, `u64`/`i64` for timestamps, `f32` for
model temperature. Every choice signals intent to the next reader.

## The scalar menu

| Type | Size | Goose example |
|------|------|---------------|
| `usize` | pointer-sized unsigned | token counts, lengths, indexes |
| `u64` / `i64` | 64-bit | timeouts, timestamps |
| `f32` / `f64` | float | `temperature` on a model config |
| `bool` | 1 byte | flags |
| `char` | 4 bytes, Unicode scalar | single characters |

Open `crates/goose/src/token_counter.rs:12`:

```rust
const MAX_TOKEN_CACHE_SIZE: usize = 1_024;
```

`1_024` — underscores are ignored; they exist so a human sees thousands at a
glance. And `usize` was picked because this constant later feeds an LRU cache
capacity. A few lines further (`crates/goose/src/token_counter.rs:15`) you see
goose's token-overhead model:

```rust
const FUNC_INIT: usize = 7;
```

Seven tokens to describe the shape of an OpenAI-style function call, plus a few
more for each property. Constants like this are why goose can *predict* token use
without calling the model.

## `let`, `mut`, and type inference

```rust
let max_cache = 1_024usize;   // explicit annotation
let mut counter = 0;          // inferred: i32 — undecorated integer literals default to i32
counter += 7;
```

`let` bindings are **immutable by default**. Need mutation? Say `mut` — and Rust
compiler warns when you say it but never mutate. Goose actually writes the
inference story at `crates/goose/src/token_counter.rs:76`:

```rust
let mut func_token_count = 0;
```

No type annotation. It becomes `usize` purely because `FUNC_INIT: usize` is added
to it later. Rust chooses the type from *use*, not from looks.

## Shadowing

```rust
let tokens = 200;
let tokens = tokens + 16;  // new binding, same name — allowed!
```

The second `tokens` *shadows* the first. Old one disappears; new one may even
have a different type. Goose uses this pattern constantly for defaults:

```rust
let tokens = vec![2048, 4096]; // pretend: cached counts from the counter
let count = tokens.len();      // usize
let count = count.max(1);      // usize again... this time from .max()
```

Shadowing is a reset button, not a mutation — no `let tokens = tokens + 16;` with
`mut` needed.

## `dbg!` — your first debugging tool

```rust
let n = dbg!(tokens.len());   // prints "[src/main.rs:12] tokens.len() = 200"
```

`dbg!` prints file:line and the expression, then **returns its value** — you can
wrap any expression in the middle of a pipeline.

<FounderLens>

Why does goose count tokens itself at all? Because provider-reported usage is
unreliable for *estimated* future cost; the cache-aware counter
(`token_counter.rs`) turns the conversation into numbers *before* the API call.
`usize` is the honest type here: these values index real memory. Tradeoff: on a
32-bit target `usize` is smaller — irrelevant for goose, which is 64-bit only.
Where it breaks: `FUNC_INIT` is explicitly annotated `usize` (as you saw), so a
future editor who changes it to 7.5 gets a type error they must consciously
resolve. That friction is the point.

</FounderLens>

<MindShift>

In TS, `number` absorbs everything, and you debug with `typeof` at runtime. In
Rust the type exists at *compile time* — you never log "is this a string or a
number?" because the compiler answered weeks ago. Once you read `usize` you know
it can't be negative, can't be a float, and (via inference) where it flows.
You're not losing dynamism; you're gaining guarantees goose relies on every
time it bills tokens.

</MindShift>
