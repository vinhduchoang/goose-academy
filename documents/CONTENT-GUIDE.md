# Content Authoring Guide (binding for all content work)

Read before writing ANY lesson content. Your output is validated by
`pnpm verify:content` in CI — invalid content fails the gate.

## Directory layout

```
content/
├─ topics.json                 # canonical topic list (use ONLY these topic strings)
├─ manifest.ts                 # GENERATED by scripts/generate-manifest.ts — never hand-edit
├─ drills.json                 # drill bank (one file, all units)
├─ exams/u0.json … u3.json     # unit exams + final exam
└─ units/u{n}/l{nn}/
   ├─ lesson.mdx               # theory, YAML frontmatter REQUIRED
   ├─ lab.md                   # lab instructions (markdown, GFM)
   ├─ test.json                # lesson test items (Zod-validated)
   └─ verify.ps1               # lab auto-check script (PowerShell 5.1)
```

Unit mapping: u0=rust-core (15 lessons l01..l15), u1=architecture (11, l01..l11),
u2=core-contribution (10, l01..l10), u3=extensions (10, l01..l10). IDs:
`u0-l01` style. Do NOT create extra folders or files.

## lesson.mdx

YAML frontmatter at top — these exact keys, nothing else required:

```yaml
---
unit: 0
unitSlug: rust-core
order: 1
id: u0-l01
slug: 01-toolchain
title: "Title here"
topics: [cargo, workspace]
durationMin: 20
cites:
  - file: Cargo.toml      # path relative to goose repo root
    line: 2               # int, the line number you actually verified
    note: what's at that line
---
```

Rules:
- `topics` MUST come from content/topics.json (verbatim strings).
- `cites` MUST be real goose files. Verify before writing (see Verification).
- Units 1-3 inclusions from the founder lens list in COURSE-PLAN §1 (e.g. "founder
  lens", "parity", "cites real file:line").
- Theory block: ~300-700 words (equivalent of <=20 min reading). Use GFM markdown.
- Cite real paths inline too (e.g. `` `crates/goose/src/agent.rs:123` ``).
- Use `<FounderLens>`, `<MindShift>` (Unit 0), `<Diff oldCode=… newCode=…>`,
  `<CodeRunnerPrompt command="…" title="…"/>` components — they are globally
  registered, no imports needed.
- **MDX attribute rules (binding):** attribute values are JSX strings. When the code
  you show contains `"` or `'`, use expression containers with JS template literals:
  `oldCode={`…`}` — inner quotes stay plain (`"`), and any literal backtick or
  `${` inside must be escaped (`\``, `\${`). Never write `\"` inside an attribute
  string, never use single-quoted attributes, and quote every `title`/`note` value
  in frontmatter (single-quote YAML strings with `'` escaped as `''`; avoid raw
  `<` `>` sequences in notes).

## lab.md

- GFM markdown, steps numbered, each step time-boxed, total 40-50 min.
- Commands MUST be PowerShell 5.1 (learners on Windows).
- Uses `$env:GOOSE_REPO` (their local goose checkout).
- Final section "## Verification" with the command `powershell -File verify.ps1`.
- Final section "## Homework" with 1-2 follow-up tasks.

## verify.ps1

PowerShell 5.1, `<# comment #>` header identifying the lesson id. Pattern
(copy the structure from content/units/u0/l01/verify.ps1):

- `param([string]$GooseRepo = $env:GOOSE_REPO)`.
- `$script:passes` / `$script:fails` counters, a `Check` helper printing
  `[PASS]` / `[FAIL]` lines.
- Print `VERIFY PASSED <n>/<n>` and `exit 0`, or `VERIFY FAILED` + `exit 1`.
- 4-7 checks. Prefer: file existence greps, `cargo metadata`, `Select-String`
  content checks, checking a notes file the learner creates in the lab.
  Avoid heavy checks (full builds) — one optional `cargo test -p …` at most,
  and only in later lessons.

## test.json

Array of 6-8 items. JSON, 2-space indent. EXACT schema:

```json
{
  "q": "question text",
  "options": ["a", "b", "c", "d"],
  "answer": 0,
  "topic": "cargo",
  "explanation": [
    "why option index 0 (+1) is wrong …",
    "why option index 0 (+2) is wrong …"
  ]
}
```

- `options`: exactly 4 strings. `answer`: int index of correct option.
  `topic`: canonical topics.json value. `explanation`: one entry per WRONG
  option, in order of the wrong options as they appear in `options`.
- Mix of question kinds: conceptual MC, "what does this print/return", and
  at least one "fix this compile error / which change unblocks this" per lesson.
- Questions must be answerable from the lesson theory/lab alone (self-contained).

## Exams (content/exams/u0.json …)

```json
{
  "unitSlug": "rust-core",
  "unitIndex": 0,
  "title": "Unit 0 Exam — Rust for Goose",
  "questions": [ …same item schema as test.json… ],
  "miniLab": {
    "title": "…",
    "instructions": "markdown text",
    "verifyScript": "…PowerShell 5.1…",
    "passMarkers": ["VERIFY PASSED", "…"]
  }
}
```

- u0/u1/u2: exactly 25 questions. u3 (final): exactly 40 questions, spanning all
  four units.
- miniLab `passMarkers`: literal strings the learner's pasted output must contain
  for the auto-grading verdict to pass (e.g. `VERIFY PASSED`, plus 2-3 concrete
  output fragments).

## drills.json

Array of at least 16 drills: `{ "id": "dr-01", "topic": "ownership",
"title": "…", "prompt": "…", "hint": "…" }`. `topic` canonical. Cover the
hardest topics across all units (ownership, borrow/lifetimes, async, serde,
parity, providers, mcp schemas, permissions…). Keep the same file structure
aligned with the plans in COURSE-PLAN §2 (remediation engine maps weak topics
to drills).

## Lesson content source of truth

Each lesson is defined by COURSE-PLAN.md §1 table rows (unit/block). Follow the
row's "Goose-grounded lab"/"Deep-lab" cell exactly — the lab MUST match it.
Where the plan references goose internals (files, crates, APIs), open the real
checkout and write what you actually saw.

## Citation verification (MANDATORY before finishing each lesson)

The local goose clone is at `C:\Users\admin\projects\goose` (pinned v1.49.0:
Cargo.toml `[workspace.package] version = "1.49.0"`).

For EVERY cite run (PowerShell):

```powershell
$f = Get-Content "C:\Users\admin\projects\goose\<file>" -ErrorAction SilentlyContinue
if (-not $f) { "MISSING FILE" }
elseif ($f.Count -lt <line>) { "LINE OUT OF RANGE" }
else { "OK: " + $f[<line>-1] }
```

Keep only cites you verified with OK output, and make the `note` describe the
actual line content you saw.

   topic from topics.json.
